# Database Ingestion Pipeline Plan (MySQL Multi-Table)

## Goal
Design an ETL pipeline to ingest all generated CSV files into a MySQL database hosted inside a local Docker container. Every domain and specific scraper technology will map to its own isolated table (e.g., `thecable_rss`, `channelstv_api`). 
**Crucial Requirement:** Every table MUST have an auto-incrementing integer column named `id`. If a CSV already has an `id` column, it will be mapped to `uid` in the database to preserve the integer `id` column. Once a CSV is fully verified as successfully ingested, it will be moved to an `archive/` folder. The ingestion process will be manually triggered via a dedicated script (`db_ingestor.py`).

## Environment & Deployment
- **Database Hosting:** The MySQL instance will be hosted locally inside a Docker container. The script will connect via `pymysql` or `mysql-connector-python` to `localhost:3306`.
- **Execution Trigger:** The ETL process is intentionally decoupled from the scrapers. You will manually run `python db_ingestor.py` whenever you are ready to ingest the accumulated CSVs.
- **Safe Archiving:** The script will mathematically verify that the number of rows successfully processed and pushed to the database matches the number of rows in the CSV file *before* executing the file move command to `scraper/data/archive/`.

## MySQL Schema & Primary Key Mappings

Because MySQL requires strict table definitions, the script will automatically create the table (if it doesn't exist) based on the CSV type before attempting to insert data.

### 1. WordPress API Output
Generated by `run_wp_scrapers.py` (e.g., `channelstv_api_2026-06-03.csv`)
```sql
CREATE TABLE IF NOT EXISTS {table_name} (
    id INT AUTO_INCREMENT PRIMARY KEY,
    uuid BIGINT,
    guid VARCHAR(500),
    slug VARCHAR(500),
    title TEXT,
    link VARCHAR(768) UNIQUE,
    category TEXT,
    date_time DATETIME
);
```
> **Deduplication Strategy:** The `link` column is marked `UNIQUE`. We will use `INSERT IGNORE INTO ...` which automatically skips duplicates without throwing errors or burning `AUTO_INCREMENT` sequences.

---

### 2. Deep XML RSS Output
Generated by the legacy deep scraper `run_all_deep_scrapers.py` (e.g., `thecable_rss_2026-06-03.csv`)
```sql
CREATE TABLE IF NOT EXISTS {table_name} (
    id INT AUTO_INCREMENT PRIMARY KEY,
    category TEXT,
    title TEXT,
    link VARCHAR(768),
    guid VARCHAR(768) UNIQUE,
    date_time VARCHAR(255),  -- RFC2822 dates can be complex, string is safest unless parsed
    subdomain VARCHAR(255)
);
```
> **Deduplication Strategy:** The `guid` column is marked `UNIQUE`.

---

### 3. Generic RSS & Domain Structure Output
Generated by `run_rss_scrapers.py` and `run_domain_scrapers.py` (e.g., `manual_thecable_data_2026-06-03.csv`)
```sql
CREATE TABLE IF NOT EXISTS {table_name} (
    id INT AUTO_INCREMENT PRIMARY KEY,
    uid VARCHAR(255),        -- Mapped from the CSV's 'id' column
    url VARCHAR(768) UNIQUE,
    title TEXT,
    date_time VARCHAR(255),
    source VARCHAR(255)
);
```
> **Deduplication Strategy:** The `url` column is marked `UNIQUE`. The original `id` column from the CSV is safely injected into the `uid` column.

## The Ingestion Logic
1. **Dynamic Tables:** The script derives the MySQL table name directly from the filename (e.g., `manual_instablog9ja_api.csv` -> `instablog9ja_api`).
2. **Idempotent Loading:** The script uses MySQL's `INSERT IGNORE INTO table (...) VALUES (...)`. If the `link`/`guid`/`url` already exists in the table, MySQL gracefully ignores the row.
3. **Data Verification:** After processing the CSV, the script compares the number of rows read to the number of rows successfully processed (inserted + ignored). If they match, the file is archived.
